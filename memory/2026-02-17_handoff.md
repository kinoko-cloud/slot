## 📋 現在の仕様（重要）

### データ取得の制約（DaiData）
- **営業中（10-22時）**: 基本統計のみ、詳細履歴なし
- **閉店後（22:50～）**: 詳細履歴取得可能
- **翌日10時～**: 前日データは営業中データに上書き

### データ保存のタイミング
1. **毎時0分（10-22時）**: 並列ワークフローでavailability.json更新
2. **23:00**: nightly-update.yml → sync_realtime_to_history.py実行
   - この時点でdata/history/に保存される
   - **23:00実行が失敗すると、その日のデータは永久に失われる**

### 表示モード
| 時間帯 | モード | データソース | 動作 |
|--------|--------|-------------|------|
| 10:00-22:49 | 営業中 | PythonAnywhere API | 動的生成 |
| 22:50-22:59 | 集計中 | - | メッセージ表示 |
| 23:00-9:59 | 結果 | Cloudflare Pages | 静的HTML |

### 2/16データの表示条件
- **基本統計あり**: ART回数、確率、推定差枚を表示

## 🎓 学んだこと

### 1. データの二重性
- availability.json: リアルタイム、営業中は不完全
- data/history/: 蓄積DB、23:00同期で完全化

### 2. 営業中制約の重要性
- DaiDataは営業中に詳細履歴を提供しない
- 23:00同期が唯一の詳細履歴取得機会
- **失敗すると永久にデータ喪失**

### 3. 表示モードの違い
- 静的サイト: history/から生成、完全データ
- 動的サイト: availability.jsonから生成、営業中は不完全

### 4. フィールド名の不統一
- `today_history` vs `history`
- `total_start` vs `games`
- これがバグの原因になる
