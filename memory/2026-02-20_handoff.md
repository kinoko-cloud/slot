## 🔧 システム構成の重要ポイント

### データ取得フロー
```
毎時0分（10-22時）
  → GitHub Actions: fetch-availability-v2.yml
  → scripts/scrapers_v2/fetch_all.py --priority-only
  → DaiData(エスパス16店舗) + Papimo(アイランド2店舗)
  → data/availability.json 更新 → commit & push
  → docs/ 静的サイト更新 → Cloudflare Pages
```

### 店舗設定ファイル（重要）
- **`scripts/fetch_daidata_availability.py`**: `DAIDATA_STORES` - 取得対象store/hall_id/units
- **`config/rankings.py`**: `STORES` - サイト表示用store設定/units
- **両方を必ず同時に更新すること！**（今回の台変動対応で両方更新済み）

### 台変動の検出・対応手順
1. `verify_units.py` またはDaidataページ直接確認
2. `machine_mismatch=True` → configから削除
3. `config/rankings.py` と `fetch_daidata_availability.py` の両方を更新
4. `data/availability.json` から古い台データを削除
5. commit & push

## 📌 重要な注意事項

1. **`-X ours` だけでは JSON混入を防げない**
   Gitのauto-merge（コンフリクトなし変更の結合）でJSONが混ざることがある。
   `save_availability` に防止ロジック追加済みなので今後は自動対応される。

2. **新宿エスパス北斗転生2は4台のみ（2/19更新）**
   台125, 126, 127, 128 のみが北斗転生2として稼働中を確認済み。

3. **final_start=0 は必ずしも問題ではない**
   - ART中 → final_start=0 は正常（ハマりG数がリセットされるため）
   - total_start=0, art=0 の組み合わせが本当の問題
